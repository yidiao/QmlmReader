# 文章页维护规范

> 作用：记录经典文章精读页的统一接口、正文接入方式、模板与常见错误。  
> 使用方式：任何新增、修复、重写文章页的任务，都必须先读本文；涉及正文 JSON 时，再读 `articles-json正文维护规范.md`。

---

## 一、页面定位

文章页现在不是单纯“静态正文页”，而是逐步明确为：

> **精读页壳 + 正文接入页**

也就是说：

- HTML 负责页面结构、视觉、Tab、图表和精读模块壳
- 正文应逐步从 `data/articles-json/...` 读取
- 精读内容可先保留在 HTML，后续再决定是否拆分独立数据层
- 若后续要拆分精读层，优先参考 `study-json精读层方案草案.md`

---

## 二、标准文件位置

文章页位于：

```text
html/articles/{Mentor}/{slug}.html
```

导师目录当前包括：

- `Mao/`
- `Marx/`
- `Engels/`
- `Lenin/`
- `Stalin/`

模板文件：

```text
html/articles/_template-v2.html
```

公共样式：

```text
css/articles-detail.css
```

公共脚本：

```text
js/article-common.js
js/article-json.js
js/article-study.js
```

---

## 三、文章页必须引入的资源

文章页通常位于 `html/articles/{Mentor}/` 下，因此相对路径一般是三级返回：

```html
<link rel="stylesheet" href="../../../css/style.css">
<link rel="stylesheet" href="../../../css/articles-detail.css">
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>
```

底部脚本推荐顺序：

```html
<script src="../../../js/article-common.js"></script>
<script src="../../../js/article-json.js"></script>
<script src="../../../js/article-study.js"></script>
<script>
    var ARTICLE_CHARTS = [...];
</script>
<script src="../../../js/site-data.js"></script>
<script src="../../../js/main.js"></script>
<script src="../../../js/darkmode.js"></script>
<script src="../../../js/cursor.js"></script>
```

关键点：

- `article-common.js` 负责 Tab、折叠、章节交互等公共逻辑
- `article-json.js` 负责从正文 JSON 渲染原文 tab
- `site-data.js` 必须在 `main.js` 之前加载
- `Chart.js` 只在使用 `ARTICLE_CHARTS` 的页面保留

## 四、HTML 结构接口

文章页 `<body>` 必须有分类：

```html
<body data-category="philosophy">
```

如果正文由 JSON 驱动，还应加：

```html
<body data-category="philosophy" data-article-json="../../../data/articles-json/Mao/★★★★★/shi-jian-lun.json">
```

如果将来精读层也试点数据化，可再追加：

```html
<body data-category="philosophy"
      data-article-json="../../../data/articles-json/Mao/★★★★★/shi-jian-lun.json"
      data-study-json="../../../data/study-json/Mao/shi-jian-lun.json">
```

取值范围：

- `philosophy`
- `economics`
- `politics`
- `party`
- `military`
- `culture`

导航占位：

```html
<div id="nav-placeholder"></div>
```

合集上下文导航：

```html
<div class="back-nav u-display-none">
    <div class="container u-max-900 u-mx-auto u-px-20">
        <a href="../../articles/articles.html" class="back-link"></a>
    </div>
</div>
```

主体容器：

```html
<main class="article-detail">
```

## 五、正文区规则

### 1. 过渡前做法

以前很多文章页把正文直接硬编码在：

```html
<div class="tab-content active" id="original">
```

里。

### 2. 当前推荐做法

正文区只保留容器，内容由 `article-json.js` 注入：

```html
<div class="tab-content active" id="original">
    <div class="original-text">
        <div class="text-intro"><p><strong>原文：</strong>正在加载文章数据…</p></div>
    </div>
</div>
```

这样 HTML 就不再承担全文存储职责。

## 六、Tab 接口

文章页当前标准 Tab：

```html
<div class="tab-nav">
    <button class="tab-btn active" onclick="switchTab('original', this)">原文</button>
    <button class="tab-btn" onclick="switchTab('reading', this)">读法提示</button>
    <button class="tab-btn" onclick="switchTab('difficulty', this)">难点解析</button>
    <button class="tab-btn" onclick="switchTab('dialogue', this)">对话空间</button>
    <button class="tab-btn" onclick="switchTab('action', this)">行动实验</button>
    <button class="tab-btn" onclick="switchTab('visual', this)">一目了然</button>
    <button class="tab-btn" onclick="switchTab('puzzle', this)">理论拼图</button>
    <button class="tab-btn" onclick="switchTab('further', this)">延伸阅读</button>
</div>
```

对应内容容器 ID：

- `original`
- `reading`
- `difficulty`
- `dialogue`
- `action`
- `visual`
- `puzzle`
- `further`

公共函数来自 `js/article-common.js`：

- `switchTab(tabId, btn)`
- `toggleChapter(titleEl)`
- `toggleAllChapters()`

---

## 七、章节折叠接口

`article-json.js` 注入的章节也必须符合：

```html
<div class="chapter">
    <h3 class="chapter-title" onclick="toggleChapter(this)">
        <span class="toggle-icon"></span>
        章节标题
    </h3>
    <div class="chapter-content">
        <p>正文段落</p>
    </div>
</div>
```

全部展开/收起按钮：

```html
<button class="chapter-toggle-all" onclick="toggleAllChapters()" id="chapterToggleBtn">收起全部</button>
```

---

## 八、图表接口

图表统一通过 `ARTICLE_CHARTS` 声明，由 `article-common.js` 在切换到 `visual` Tab 时初始化。

```js
var ARTICLE_CHARTS = [
    {
        id: 'radarChart',
        config: {
            type: 'radar',
            data: {},
            options: {}
        }
    }
];
```

硬规则：

- `ARTICLE_CHARTS[i].id` 必须和 `<canvas id="...">` 一致
- 不要在页面里直接 `new Chart(...)`
- 不要在隐藏 Tab 中提前初始化图表

---

## 九、下载入口边界

现在的约定是：

- **下载中心负责文章下载入口**
- **精读页不再强制提供下载按钮**

说明：

- 文章正文下载仍由 `js/download-export.js` 负责实现
- 但入口主要放在 `html/downloads/downloads.html`
- 精读页的职责是阅读、精读组织与正文展示，不必再额外挂下载浮窗

---

## 十、常见错误

1. HTML 里继续硬编码全文，同时又接入 `data-article-json`
2. 页面已 JSON 化，却忘记引入 `article-json.js`
3. 精读页继续保留旧下载浮窗，造成页面职责混乱
4. 页面目录和正文 JSON 的 `mentor` 不一致
5. 把精读模块和正文源混成一个难以维护的大块 HTML

---

## 十一、推荐迁移顺序

1. 先把正文整理进 `data/articles-json/...`
2. 再让页面 `<body>` 接上 `data-article-json`
3. 原文 tab 改为占位容器
4. 保留现有精读模块不动
5. 下载入口统一收束到下载中心
