# 母站架构维护

> 作用：记录 QmlmReader 母站的真实代码架构、公共接口和维护边界。  
> 使用方式：AI 接任务前先读 `项目维护.md`，如果任务涉及母站页面、导航、搜索、数据源或下载中心，再读本文。

---

## 一、架构结论

QmlmReader 当前是静态站点为主、原生 JavaScript 组织交互、JSON 数据驱动部分页面的架构。

主线如下：

```text
index.html
  -> html/index.html
      -> 公共导航：js/main.js
      -> 公共样式：css/style.css
      -> 公共数据：js/site-data.js
      -> 搜索：js/search.js
      -> 黑夜模式：js/darkmode.js
      -> 自定义光标：js/cursor.js
```

重点判断：

- `html/` 是页面主体目录。
- `js/main.js` 是全站导航、面包屑、合集导航、章节侧边栏等母站公共逻辑核心。
- `js/site-data.js` 是 `_tools/build_data.py` 生成的数据聚合产物。
- `data/*.json` 与 `downloads/manifest.unified.json` 是长期应收敛的权威数据源。
- `api/translate.js` 是武器库/工具功能的 Vercel 后端代理，不是母站静态页面的必要依赖。

---

## 二、关键文件位置

### 页面入口

- `index.html`：根入口，只做跳转到 `html/index.html`。
- `html/index.html`：真正首页。
- `html/articles/articles.html`：文章列表与合集展示页。
- `html/downloads/downloads.html`：下载中心。
- `html/experimental/experimental.html`：武器库总入口。

### 公共脚本

- `js/main.js`：导航注入、面包屑、合集导航、章节导航、页面卡片动画等。
- `js/search.js`：搜索索引读取与搜索结果渲染。
- `js/site-data.js`：生成数据，挂到 `window.SITE_DATA`。
- `js/darkmode.js`：`toggleDarkMode()` 与 `body.dark-mode`。
- `js/cursor.js`：自定义光标。
- `js/article-common.js`：文章详情页公共接口。

### 公共样式

- `css/style.css`：全站基础样式、导航、首页、列表页通用组件、黑夜模式等。
- `css/articles-detail.css`：文章详情页统一样式。

### 数据与构建

- `data/articles.json`：文章元数据。
- `data/collections.json`：合集定义。
- `data/gallery.json`：文艺搜索数据。
- `data/rectify.json`：正名搜索数据。
- `data/articles_structure.json`：文章章节结构信息。
- `downloads/manifest.unified.json`：下载中心统一清单。
- `_tools/build_data.py`：生成 `js/site-data.js`。
- `_tools/add_site_data_script.py`：批量给 HTML 注入 `site-data.js`。
- `_tools/sync_manifest.py`：把 `manifest.unified.json` 同步到 `manifest.json`。

## 三、全站页面接口

所有正式页面原则上应具备：

```html
<link rel="stylesheet" href="相对路径/css/style.css">
<div id="nav-placeholder"></div>
<script src="相对路径/js/site-data.js"></script>
<script src="相对路径/js/main.js"></script>
<script src="相对路径/js/darkmode.js"></script>
<script src="相对路径/js/cursor.js"></script>
```

当前实测：

- `html/` 下 82 个 HTML 页面均包含 `nav-placeholder`。
- `html/` 下 82 个 HTML 页面均包含 `js/site-data.js`。
- 所有引用 `main.js` 的页面都已经在它之前引用了 `site-data.js`。

维护规则：

- 新页面必须放入 `html/` 下。
- 新页面必须放置 `<div id="nav-placeholder"></div>`。
- 如果使用 `main.js` 或 `search.js`，必须先引入 `site-data.js`。
- 页面层级不同，脚本路径必须按相对层级调整。

## 四、`main.js` 公共接口

`js/main.js` 当前负责：

- 自动注入导航栏。
- 生成面包屑。
- 导航高亮。
- 文章列表筛选的通用辅助函数。
- 长文章章节侧边栏。
- 文章合集上下文导航。
- 合集目录弹窗。
- 页面卡片入场动画。

### 导航注入接口

页面需要：

```html
<div id="nav-placeholder"></div>
```

`main.js` 会用 `outerHTML` 替换成完整 `<header class="site-header">...`。

### 面包屑接口

`main.js` 内部维护 `PATH_LABELS`，通过 URL 路径生成面包屑。

风险：新目录或新页面如果未加入 `PATH_LABELS`，面包屑会显示 slug 原文。

### 合集导航接口

`main.js` 使用全局变量：

```js
var COLLECTIONS = [...];
if (window.SITE_DATA && window.SITE_DATA.collections) {
    COLLECTIONS = window.SITE_DATA.collections;
}
```

当前状态：仍保留硬编码 `COLLECTIONS` 作为兜底，但优先使用 `window.SITE_DATA.collections`。

长期目标：确认所有页面均稳定加载 `site-data.js` 后，删除硬编码 `COLLECTIONS`。

## 五、搜索接口

`js/search.js` 使用：

```js
var articleIndex = (window.SITE_DATA && window.SITE_DATA.articleIndex) ? window.SITE_DATA.articleIndex : [...];
var galleryIndex = (window.SITE_DATA && window.SITE_DATA.galleryIndex) ? window.SITE_DATA.galleryIndex : [...];
var rectifyIndex = (window.SITE_DATA && window.SITE_DATA.rectifyIndex) ? window.SITE_DATA.rectifyIndex : [...];
```

搜索入口依赖页面元素：

```html
<input id="searchInput">
<div id="searchResults"></div>
```

主要函数：

- `performSearch()`：执行搜索并渲染结果。
- `updateFilters(author)`：更新作者筛选。
- `resetFilters()`：重置筛选。

当前状态：搜索已优先读取 `window.SITE_DATA`，但仍保留内嵌索引兜底。

长期目标：删除内嵌索引，把 `data/articles.json`、`data/gallery.json`、`data/rectify.json` 作为权威源。

## 六、全局视觉变量

`css/style.css` 的核心变量：

```css
:root {
    --primary-color: #c41e3a;
    --primary-dark: #8b0000;
    --secondary-color: #ffd700;
    --text-color: #333;
    --text-light: #666;
    --bg-color: #f5f5f5;
    --card-bg: #fff;
    --border-color: #ddd;
    --shadow: 0 2px 8px rgba(0,0,0,0.1);
    --shadow-hover: 0 4px 16px rgba(0,0,0,0.15);
}
```

黑夜模式通过：

```css
body.dark-mode { ... }
```

并由 `js/darkmode.js` 的 `toggleDarkMode()` 控制。

维护规则：

- 新公共组件优先使用这些变量。
- 不要在单页硬编码一整套重复色板。
- 黑夜模式必须同步考虑。

## 七、当前架构风险

### 已确认风险

1. 数据源统一已半完成，但仍存在大量兜底硬编码。
2. `data/articles.json` 只有 28 篇文章，实际文章 HTML 有 29 篇，缺少 `articles/Lenin/lun-wo-guo-ge-ming.html` 的元数据。
3. `html/articles/Mao/shi-jian-lun.html` 和 `html/articles/Mao/mao-dun-lun.html` 仍未使用新文章公共接口：缺 `ARTICLE_CHARTS`、`DOWNLOAD_LINKS`、`article-common.js`。
4. `downloads/manifest.unified.json` 指向 3 个中国宣传画 ZIP，但 `downloads/posters/` 下未找到对应文件。
5. `main.js` 中仍有完整 `COLLECTIONS` 硬编码，和 `site-data.js` 并存。
6. `articles.html`、`downloads.html` 页面内仍有大段内嵌数据，虽然已优先读取 `SITE_DATA`。

### 改造方向

优先顺序建议：

1. 补齐 `articles.json` 缺失文章。
2. 将实践论、矛盾论迁移到文章公共接口。
3. 修正下载 manifest 与真实文件的差异。
4. 删除 `main.js`、`articles.html`、`downloads.html` 中的内嵌兜底数据。
5. 把导航路径标签、下载数据、搜索数据完全纳入统一构建。
