# 母站架构维护

> 作用：记录 QmlmReader 母站的真实代码架构、公共接口和维护边界。  
> 使用方式：AI 接任务前先读 `项目维护.md`；涉及母站页面、导航、搜索、数据源或下载中心时，再读本文。

---

## 一、架构结论

QmlmReader 当前是：

- **静态站点为主体**
- **原生 JavaScript 负责交互**
- **索引层由 JSON 聚合驱动**
- **正文层正逐步从 HTML 内嵌迁往 `data/articles-json`**

主线如下：

```text
index.html
  -> html/index.html
      -> 公共导航：js/main.js
      -> 公共样式：css/style.css
      -> 站点聚合数据：js/site-data.js
      -> 搜索：js/search.js
      -> 黑夜模式：js/darkmode.js
      -> 自定义光标：js/cursor.js
```

对于文章系统，新增的明确关系是：

```text
html/articles/{Mentor}/{slug}.html
  -> 精读页壳 / Tab / 图表
  -> 原文区逐步改为读取 data/articles-json/{Mentor}/{Star}/{slug}.json
  -> 下载由 js/download-export.js 从正文源导出 TXT / DOCX
  -> 下载入口主留在 html/downloads/downloads.html
```

---

## 二、关键文件位置

### 页面入口

- `index.html`：根入口，只做跳转到 `html/index.html`
- `html/index.html`：真正首页
- `html/articles/articles.html`：文章列表与合集展示页
- `html/downloads/downloads.html`：下载中心
- `html/experimental/experimental.html`：武器库总入口

### 公共脚本

- `js/main.js`：导航注入、面包屑、合集导航、章节导航、页面卡片动画等
- `js/search.js`：搜索索引读取与搜索结果渲染
- `js/site-data.js`：生成数据，挂到 `window.SITE_DATA`
- `js/darkmode.js`：`toggleDarkMode()` 与 `body.dark-mode`
- `js/cursor.js`：自定义光标
- `js/article-common.js`：文章详情页公共接口
- `js/article-json.js`：文章原文 JSON 渲染接口
- `js/article-study.js`：文章精读层 JSON 渲染接口
- `js/download-export.js`：文章 TXT / DOCX 导出接口

### 公共样式

- `css/style.css`：全站基础样式、导航、首页、列表页通用组件、黑夜模式等
- `css/articles-detail.css`：文章详情页统一样式

### 数据与构建

- `data/articles.json`：文章索引
- `data/articles-json/`：文章正文数据
- `data/articles-json/_meta/`：正文层辅助清单与校验结果
- `data/collections.json`：合集定义
- `data/gallery.json`：文艺搜索数据
- `data/rectify.json`：正名搜索数据
- `data/articles_structure.json`：章节辅助信息
- `downloads/manifest.unified.json`：下载中心清单
- `_tools/build_data.py`：生成 `js/site-data.js`

## 三、全站页面接口

所有正式页面原则上应具备：

```html
<link rel="stylesheet" href="相对路径/css/style.css">
<div id="nav-placeholder"></div>
<script src="相对路径/js/site-data.js"></script>
<script src="相对路径/js/main.js"></script>
<script src="相对路径/js/darkmode.js"></script>
<script src="相对路径/js/cursor.js"></script>
```

维护规则：

- 新页面必须放入 `html/` 下
- 新页面必须放置 `<div id="nav-placeholder"></div>`
- 如果使用 `main.js` 或 `search.js`，必须先引入 `site-data.js`
- 页面层级不同，脚本路径必须按相对层级调整

---

## 四、`main.js` 公共接口

`js/main.js` 当前负责：

- 自动注入导航栏
- 生成面包屑
- 导航高亮
- 文章列表筛选辅助逻辑
- 长文章章节侧边栏
- 文章合集上下文导航
- 合集目录弹窗
- 页面卡片入场动画

### 合集导航接口

`main.js` 使用：

```js
var COLLECTIONS = [...];
if (window.SITE_DATA && window.SITE_DATA.collections) {
    COLLECTIONS = window.SITE_DATA.collections;
}
```

当前状态：仍保留硬编码兜底，但优先读取 `window.SITE_DATA.collections`。

长期目标：确认站点稳定后，删除硬编码兜底。

---

## 五、搜索接口

`js/search.js` 当前使用：

```js
var articleIndex = (window.SITE_DATA && window.SITE_DATA.articleIndex) ? window.SITE_DATA.articleIndex : [...];
var galleryIndex = (window.SITE_DATA && window.SITE_DATA.galleryIndex) ? window.SITE_DATA.galleryIndex : [...];
var rectifyIndex = (window.SITE_DATA && window.SITE_DATA.rectifyIndex) ? window.SITE_DATA.rectifyIndex : [...];
```

说明：

- 搜索目前仍主要基于索引层
- 不是直接全文读取 `articles-json`
- 后续如做正文级搜索，应单独设计，不要直接把全文塞进 `site-data.js`

## 六、文章系统与母站关系

### 当前正确分工

#### 索引层
- `data/articles.json`
- `js/site-data.js`
- 用于列表、合集、下载入口、搜索基础信息

#### 正文层
- `data/articles-json/{Mentor}/{Star}/{slug}.json`
- 用于文章原文、段落、章节、下载导出

#### 页面层
- `html/articles/{Mentor}/{slug}.html`
- 用于精读结构、视觉、交互、阅读组织

这三层不要再混写成一套。

---

## 七、当前架构风险

### 已确认风险

1. `data/articles.json` 目前仍缺《论我国革命》索引条目
2. 绝大多数经典文章页仍未完成“HTML 壳 + JSON 正文”迁移
3. `articles.html`、`downloads.html`、`main.js`、`search.js` 仍残留大段兜底数据
4. `articles_structure.json` 与未来结构化正文可能出现双重维护风险
5. imported 文章已大规模入库，但尚未接入统一正文维护模式

### 当前优先改造方向

1. 继续结构化 `data/articles-json`
2. 把更多经典文章页接入 `data-article-json`
3. 逐步减少 HTML/JS 内嵌兜底数据
4. 保持下载从正文源导出，而不是回到静态文件堆模式
