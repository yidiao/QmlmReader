# QmlmReader 项目维护文档

> 用途：这是项目总括性维护手册，只保留方向、入口和任务分发。  
> 使用方式：人工在这里记录维护命令和布局；AI 接任务时先读本文，再按任务类型读取对应专题文档。  
> 原则：总文档不堆细节。接口、变量、函数、页面规范和问题清单放入专题文档。

---

## 一、给你看

### 1.1 项目定位

QmlmReader 是一个以马克思主义经典文献、导师专题、理论整理、资料下载和实验工具为核心的静态网站。

它的核心目标不是简单堆文章，而是建立一个可持续维护的阅读与学习平台：文章能被搜索、归入合集、形成理论联结，并和下载资源、专题页面、工具页面保持一致。

### 1.2 当前架构判断

当前项目仍以静态站点为主体：

- 页面主体在 `html/`
- 全站公共样式在 `css/style.css`
- 文章详情样式在 `css/articles-detail.css`
- 公共交互在 `js/main.js`
- 文章页交互在 `js/article-common.js`
- 统一数据产物是 `js/site-data.js`
- 数据源正在向 `data/*.json` 和 `downloads/manifest.unified.json` 收敛
- 武器库工具保持模块自治，不强行并入母站数据源

### 1.3 当前维护主线

长期维护优先级：

1. 修正文章正文与文章元数据缺口
2. 完成数据源统一改造，减少重复维护
3. 统一文章页接口，消除旧模板例外
4. 整理下载资源和资源质量标记
5. 补全专题栏目内容
6. 再做留言板、实验工具、全文搜索等扩展功能

### 1.4 近期明确问题

已结合真实代码发现：

- `data/articles.json` 缺少 `html/articles/Lenin/lun-wo-ge-ming.html` 对应元数据
- `html/articles/Mao/shi-jian-lun.html` 和 `html/articles/Mao/mao-dun-lun.html` 仍未接入新文章公共接口
- 中国宣传画不再要求本地 ZIP 托管，后续改为百度网盘外链入口
- 下载中心需要整体重构：单篇文章统一 Word，著作类统一 PDF，下载源和展示层分离
- 数据源统一已部分落地，但 `main.js`、`search.js`、`articles.html`、`downloads.html` 仍保留大段内嵌兜底数据

详细见：`架构问题清单.md`。

### 1.5 人工维护原则

- 总文档只写命令、方向、任务布局和文档索引
- 细节写入专题文档
- 新任务要尽量引用专题文档名称或问题编号
- 不把历史过程日志堆回总文档
- 不让同一份数据长期同时存在于 HTML、JS、JSON 三处

### 2.3 母站关键接口速查

全站页面公共接口：

```html
<div id="nav-placeholder"></div>
<script src="相对路径/js/site-data.js"></script>
<script src="相对路径/js/main.js"></script>
<script src="相对路径/js/darkmode.js"></script>
<script src="相对路径/js/cursor.js"></script>
```

统一数据对象：

```js
window.SITE_DATA = {
  collections: [],
  articles: [],
  articleIndex: [],
  galleryIndex: [],
  rectifyIndex: [],
  downloadData: {}
};
```

全局视觉变量：

```css
--primary-color
--primary-dark
--secondary-color
--text-color
--text-light
--bg-color
--card-bg
--border-color
--shadow
--shadow-hover
```

黑夜模式：

```js
toggleDarkMode()
```

对应 CSS：

```css
body.dark-mode
```

### 2.5 数据源关键接口速查

权威数据源：

```text
data/articles.json
data/collections.json
data/gallery.json
data/rectify.json
downloads/manifest.unified.json
```

生成命令：

```bash
python _tools/build_data.py --check
python _tools/build_data.py --write
```

下载 manifest 同步：

```bash
python _tools/sync_manifest.py
```

### 2.6 当前状态判断

当前数据源统一不是“未开始”，而是“半完成”：

- `site-data.js` 已生成并被 82 个 HTML 页面引用
- `main.js`、`search.js`、`articles.html`、`downloads.html` 已优先读取 `SITE_DATA`
- 但旧硬编码兜底仍存在，后续应逐步删除

### 2.7 AI 修改规则

- 先确认任务属于母站、文章页、数据源、下载中心还是武器库
- 先读对应专题文档，再读代码
- 涉及数据源时优先改 JSON，再运行构建脚本
- 涉及文章页时优先套 `html/articles/_template-v2.html` 和 `js/article-common.js`
- 涉及视觉时优先使用统一 CSS 变量，不要在单页发明新色板
- 涉及下载时核对 manifest 与真实文件是否一致
- 不要把工具私有数据强行并入母站数据源
