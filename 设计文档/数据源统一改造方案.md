# QmlmReader 数据源统一改造方案

> 目标：把目前分散在 HTML/JS/JSON 中的数据收敛到“单一数据源 + 构建生成”，减少新增文章/工具时的重复维护。
> 适用对象：文章、合集、搜索索引、下载中心、导航面包屑等母站公共数据。

---

## 一、现状问题

| 数据 | 当前分散位置 | 问题 |
|---|---|---|
| 合集 | `data/collections.json` + `js/main.js` 硬编码 `COLLECTIONS` + `html/articles/articles.html` 内嵌 | 三处维护，容易不一致 |
| 文章元信息 | `html/articles/*/*.html` 内嵌 + `js/search.js` 的 `articleIndex` + `data/articles_structure.json` | 搜索索引漏文章、文章页与索引不同步 |
| 搜索索引 | `js/search.js` 内嵌 `articleIndex` / `galleryIndex` / `rectifyIndex` | 纯前端手工维护，新增内容必须同步改 JS |
| 下载中心 | `html/downloads/downloads.html` 内嵌 `articlePDFs` / `rectifyPDFs` / `posterZIPs` | 新增下载资源要改页面 |
| 导航/面包屑 | `js/main.js` 中 `PATH_LABELS` + 各页面 `nav-placeholder` | 目前导航已收敛，但页面分类标签仍可统一到数据 |
| 文章章节 | `data/articles_structure.json` + HTML 内 `.chapter` | 结构数据与页面内容分离，可用于生成目录/侧边栏 |

---

## 二、目标架构

```text
data/
├── articles.json          # 文章元数据（权威）
├── collections.json       # 合集定义（权威，已有）
├── downloads/manifest.json# 下载资源（权威，已有）
├── history-events.js      # 历史事件（可保留）
└── site-meta.json         # 导航、面包屑、站点统计等

        │  _tools/build_data.py 生成
        ▼
js/
├── site-data.js           # 生成后的 COLLECTIONS / SEARCH_INDEX / DOWNLOAD_DATA
├── main.js                # 改为读取 site-data.js，删除硬编码 COLLECTIONS
└── search.js              # 改为读取 site-data.js，删除内嵌索引
```

### 关键原则

1. **HTML 仍是文章内容的主要载体**，但文章“元数据”全部进 `articles.json`。
2. **不在 HTML/JS 中手工维护列表数据**，所有列表页数据由构建脚本生成。
3. **工具私有数据**（青马题库、马列体导师 Prompt、样板戏 Prompt 等）不强行纳入母站统一数据，保持模块自治。
4. **构建产物提交到仓库**，保证 GitHub Pages 静态托管无需额外构建步骤也能运行。

```json
  "title": "实践论",

    "txt": "data/shi-jian-lun.txt",
    "pdf": "downloads/xxx.pdf"
  },
  "chapterFile": "data/articles_structure.json"

```

### 2. `data/collections.json`

保持现有结构，但确保：

- `slug` 与 `articles.json` 的 `slug` 一一对应；
- 不再在 `main.js` / `articles.html` 中复制合集数组；
- 构建时校验 `slug` 是否有对应 HTML 文件。

### 3. 搜索索引生成

从 `articles.json` + `galleryIndex` 数据 + `rectifyIndex` 数据 + `historyData` 生成 `js/site-data.js`：

```js
window.SITE_DATA = {
  collections: [...],
  articleIndex: [...],
  galleryIndex: [...],
  rectifyIndex: [...],
  downloadData: {...}
};
```

### 4. 下载中心数据

把 `html/downloads/downloads.html` 内嵌数组迁移到 `downloads/manifest.json`，页面通过 `site-data.js` 渲染。

## 四、改造步骤

### Phase 1：先建数据，不改页面

1. 从现有 `js/search.js`、`data/collections.json`、`html/downloads/downloads.html` 提取文章/合集/下载元数据，生成 `data/articles.json`。
2. 保留 `data/collections.json` 为唯一合集数据，补充缺失的 `subtitle`、`desc`、`cover`。
3. 将 `downloads/manifest.json` 补全为下载中心权威数据。

### Phase 2：写构建脚本

1. 新建 `_tools/build_data.py`。
2. 输入：`data/articles.json`、`data/collections.json`、`downloads/manifest.json`、`data/history-events.js`。
3. 输出：`js/site-data.js`，包含 `COLLECTIONS`、`ARTICLE_INDEX`、`GALLERY_INDEX`、`RECTIFY_INDEX`、`DOWNLOAD_DATA`。
4. 脚本同时执行校验：
   - 每个 `ready` 文章是否有 HTML 文件；
   - 每个合集 slug 是否能在 `articles.json` 中找到；
   - 搜索索引是否覆盖全部 `ready` 文章；
   - 下载链接指向的文件是否存在。

### Phase 3：改造前端

1. `js/main.js`：
   - 删除硬编码 `var COLLECTIONS = [...]`；
   - 改为读取 `window.SITE_DATA.collections`。
2. `js/search.js`：
   - 删除内嵌 `articleIndex` / `galleryIndex` / `rectifyIndex`；
   - 改为读取 `window.SITE_DATA.*`。
3. `html/articles/articles.html`：
   - 合集弹窗和文章卡片数据改为由 `site-data.js` 渲染，或由构建脚本生成静态 HTML。
4. `html/downloads/downloads.html`：
   - 改为从 `window.SITE_DATA.downloadData` 渲染。
5. 所有页面确认引用 `js/site-data.js` 的顺序在 `main.js` / `search.js` 之前。

### Phase 4：清理与验证

1. 删除不再使用的内嵌数据副本。
2. 运行 `_tools/build_data.py` 生成最新 `site-data.js`。
3. 手工回归：
   - 首页搜索；
   - 文章列表筛选；
   - 合集弹窗；
   - 文章详情页上/下一章；
   - 下载中心筛选与统计。

---

## 五、预期收益

- 新增一篇文章只需改 `articles.json`，重新生成即可同步搜索、合集、列表、下载。
- 合集数据不再三处同步。
- 搜索索引不再漏文章。
- 下载中心不再手工改页面。
- 为未来“全文搜索 / 标签系统 / 阅读进度”打好数据基础。

---

## 六、不做的事

- 不重构文章 HTML 的 7-Tab 内容结构；
- 不强行把青马、马列体、样板戏等工具私有数据并入母站数据；
- 不引入前端框架；
- 不改变 GitHub Pages + Vercel 的部署方式。

## 八、数据模型详细设计

### 8.1 `data/articles.json`

建议使用数组结构，每篇文章一条记录：

```json
{
  "slug": "shi-jian-lun",
  "title": "实践论",
  "author": "毛泽东",
  "authorKey": "mao",
  "date": "1937年7月",
  "year": "1937",
  "priority": 5,
  "category": "哲学基础",
  "type": "philosophy",
  "keywords": ["认识论", "辩证法", "实践"],
  "file": "articles/Mao/shi-jian-lun.html",
  "ready": true,
  "collections": ["mao-vol1", "mao-philosophy"],
  "downloads": {
    "txt": "data/shi-jian-lun.txt",
    "pdf": "downloads/shi-jian-lun.pdf"
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `slug` | ✅ | 文章唯一标识，也是 URL 文件名 |
| `title` | ✅ | 文章标题 |
| `author` | ✅ | 展示用作者名 |
| `authorKey` | ✅ | 筛选用作者 key：`marx/engels/lenin/stalin/mao` |
| `date` | ✅ | 写作日期展示文本 |
| `year` | ✅ | 年份，用于时间轴/搜索 |
| `priority` | ✅ | 1–5 星级 |
| `category` | ✅ | 展示分类 |
| `type` | ✅ | 分类 key：`philosophy/economics/politics/party/military/culture` |
| `keywords` | ✅ | 搜索关键词 |
| `file` | ✅ | 相对 `html/` 的 HTML 路径 |
| `ready` | ✅ | 是否已实装 |
| `collections` | ⬜ | 所属合集 id 数组 |
| `downloads` | ⬜ | TXT/PDF 下载路径 |

### 8.2 `data/collections.json`

保持现有结构，但要求：

- `id` 全局唯一；
- `articles[].slug` 必须能在 `articles.json` 中找到；
- `articles[].status` 由 `ready` 派生，避免手工不一致；
- 不再在 `main.js`、`articles.html` 中复制该数组。

建议统一结构：

```json
{
  "id": "mao-vol1",
  "title": "毛泽东选集 · 第一卷",
  "subtitle": "1925—1937 · 第一次、二次国内革命战争时期",
  "cover": "☭",
  "desc": "...",
  "articles": [
    {
      "title": "中国社会各阶级的分析",
      "slug": null,
      "status": "wip"
    }
  ]
}
```

### 8.3 `downloads/manifest.json`

在现有基础上补充字段：

```json
{
  "type": "pdf",
  "author": "毛泽东",
  "title": "实践论",
  "file": "downloads/pdfs/shi-jian-lun.pdf",
  "size": "1.2MB",
  "quality": "text",
  "slug": "shi-jian-lun"
}
```

其中 `quality` 建议取值：

- `text`：文本转 PDF；
- `scan`：扫描版 PDF；
- 下载中心可据此显示“文本版/扫描版”。

### 8.4 生成产物 `js/site-data.js`

```js
window.SITE_DATA = {
  generatedAt: "2026-...",
  collections: [],
  articles: [],
  articleIndex: [],
  galleryIndex: [],
  rectifyIndex: [],
  downloadData: []
};
```

## 九、构建脚本设计

### 9.1 文件位置

`_tools/build_data.py`

### 9.2 命令设计

```bash
# 只检查数据完整性，不写文件
python _tools/build_data.py --check

# 生成 js/site-data.js
python _tools/build_data.py --write
```

### 9.3 脚本职责

1. 读取：
   - `data/articles.json`
   - `data/collections.json`
   - `downloads/manifest.json`
   - `data/history-events.js`（可选解析）
2. 校验：
   - 所有 `ready: true` 文章必须有对应 HTML 文件；
   - 所有 `collections[].articles[].slug` 必须存在；
   - 所有搜索索引条目必须有 `file` 指向的文件；
   - 所有下载链接必须有对应文件；
   - 所有 `authorKey`、`type`、`priority` 取值合法；
   - 不允许重复 `slug`。
3. 生成 `js/site-data.js`。

### 9.4 生成内容

- `collections`：来自 `collections.json`；
- `articles`：来自 `articles.json`；
- `articleIndex`：由 `articles.json` 中 `ready: true` 的文章生成；
- `galleryIndex`：从 `search.js` 迁移到 `data/gallery.json` 或保留在构建配置中；
- `rectifyIndex`：从 `search.js` 迁移到 `data/rectify.json` 或保留在构建配置中；
- `downloadData`：来自 `downloads/manifest.json`。

## 十、前端改造细节

### 10.1 `main.js`

现状：

```js
var COLLECTIONS = [ ...大量硬编码... ];
```

改为：

```js
var COLLECTIONS = window.SITE_DATA ? window.SITE_DATA.collections : [];
```

注意：

- 页面必须在 `main.js` 之前引入 `js/site-data.js`；
- 如果 `site-data.js` 加载失败，可保留一个空数组兜底，但不应再维护硬编码数据。

### 10.2 `search.js`

现状：

```js
const articleIndex = [ ... ];
const galleryIndex = [ ... ];
const rectifyIndex = [ ... ];
```

改为：

```js
const articleIndex = window.SITE_DATA ? window.SITE_DATA.articleIndex : [];
const galleryIndex = window.SITE_DATA ? window.SITE_DATA.galleryIndex : [];
const rectifyIndex = window.SITE_DATA ? window.SITE_DATA.rectifyIndex : [];
```

### 10.3 `downloads.html`

- 删除页面内 `articlePDFs` / `rectifyPDFs` / `posterZIPs` 数组；
- 改为从 `window.SITE_DATA.downloadData` 读取；
- 筛选按钮和统计数字由 JS 根据数据自动生成。

### 10.4 `articles.html`

- 文章卡片可以继续保留静态 HTML，但合集弹窗数据改为读取 `window.SITE_DATA.collections`；
- 后续如果文章数量继续增长，可再改为由 `articles.json` 生成整个列表。

## 十一、迁移顺序

### 阶段 A：数据准备

1. 从 `search.js` 提取 `articleIndex` 到 `data/articles.json`；
2. 从 `collections.json` 补齐 `subtitle/desc/cover`；
3. 从 `downloads.html` 提取下载数据到 `downloads/manifest.json`；
4. 提交 JSON 文件，暂不改前端。

### 阶段 B：构建脚本

1. 写 `_tools/build_data.py`；
2. 先只跑 `--check`，修复所有校验错误；
3. 再跑 `--write` 生成 `js/site-data.js`；
4. 提交生成文件。

### 阶段 C：前端切换

1. 在所有需要数据的页面引入 `js/site-data.js`；
2. 改 `main.js`；
3. 改 `search.js`；
4. 改 `downloads.html`；
5. 保留旧数据一段时间，作为回退。

### 阶段 D：清理旧数据

1. 确认搜索、合集、下载中心全部正常后；
2. 删除 `main.js` 中的硬编码 `COLLECTIONS`；
3. 删除 `search.js` 中的内嵌索引数组；
4. 删除 `downloads.html` 中的内嵌数据数组。

## 十三、风险与回退

| 风险 | 应对 |
|---|---|
| `site-data.js` 未加载导致页面空白 | 所有页面统一在 `<head>` 或 `<body>` 顶部引入，并在 JS 中做空数组兜底 |
| 数据迁移过程中遗漏文章 | `--check` 强制校验 `ready` 文章必须存在 HTML |
| 旧数据与 JSON 不一致 | 切换前保留旧文件，切换后通过 diff 核对 |
| 静态托管不支持动态构建 | 构建产物 `js/site-data.js` 直接提交仓库 |
| 误改 experimental/toolkit 页面 | 本方案不涉及任何页面迁移或删除，只改数据读取方式 |

## 十四、后续可扩展

- 全文搜索：`articles.json` 可扩展 `fullText` 或引用正文路径；
- 标签系统：`keywords` 可直接生成标签云；
- 阅读进度：以 `slug` 为主键，在 localStorage 中记录进度；
- 文章统计：由 `articles.json` 自动生成“文章总数/ready 数/wip 数”。

## 十五、新增一篇文章的完整对接流程

以后文章数量增加后，新增文章不需要再手工同步“搜索、合集、下载、列表”，只需要做两件事：

1. 创建文章 HTML；
2. 在 `data/articles.json` 中登记这篇文章。

然后运行：

```bash
python _tools/build_data.py --write
```

脚本会自动生成新的 `js/site-data.js`，搜索、合集、下载中心、文章列表全部读取这份数据，因此会自动更新。

---

### 15.1 标准步骤

#### 第 1 步：创建文章 HTML

在对应导师目录下新增：

```text
html/articles/Mao/xxx.html
```

文章内容仍然使用现有模板规范，本次数据统一不改文章 HTML 结构。

#### 第 2 步：在 `data/articles.json` 中登记

示例：

```json
{
  "slug": "xxx",
  "title": "文章标题",
  "author": "毛泽东",
  "authorKey": "mao",
  "date": "1938年1月",
  "year": "1938",
  "priority": 4,
  "category": "军事战略",
  "type": "military",
  "keywords": ["关键词1", "关键词2"],
  "file": "articles/Mao/xxx.html",
  "ready": true,
  "collections": ["mao-military"],
  "downloads": {
    "txt": "data/xxx.txt",
    "pdf": "downloads/xxx.pdf"
  }
}
```

#### 第 3 步：如果需要加入合集

在 `data/collections.json` 对应合集的 `articles` 数组中增加：

```json
{
  "title": "文章标题",
  "slug": "xxx",
  "status": "ready"
}
```

如果 `data/articles.json` 的 `collections` 字段已填写，构建脚本也可以选择**自动反向生成**合集关系，避免两处填写。

#### 第 4 步：运行构建脚本

```bash
python _tools/build_data.py --check
python _tools/build_data.py --write
```

- `--check` 会检查 HTML 是否存在、slug 是否重复、合集引用是否正确；
- `--write` 会重新生成 `js/site-data.js`。

#### 第 5 步：提交生成产物

将以下内容一起提交：

```text
html/articles/Mao/xxx.html
data/articles.json
data/collections.json（如修改）
js/site-data.js
```

---

### 15.2 脚本自动对接了什么

| 接口 | 自动行为 |
|---|---|
| 搜索 | `articleIndex` 从 `articles.json` 中 `ready: true` 的文章生成，新文章自动可搜 |
| 文章列表 | 如果列表页改为数据驱动，新文章自动出现 |
| 合集弹窗 | 根据 `collections` 或 `collections.json` 自动关联 |
| 上/下一章 | 合集顺序来自 `collections.json`，新文章按顺序自动进入 |
| 下载中心 | 根据 `articles.json` 的 `downloads` 字段自动生成下载项 |
| 统计数字 | 文章总数、ready 数、wip 数由数据自动计算 |

---

### 15.3 如果新增的是 WIP 文章

未完成文章可以登记为：

```json
{
  "slug": "xxx",
  "ready": false
}
```

构建脚本会：

- 不把它写入 `articleIndex`，避免搜索到未完成页面；
- 在合集目录中仍显示为“筹备中”；
- 文章列表/统计中计入 `wip` 数量。

---

### 15.4 建议：合集关系只维护一处

两种可选方案：

#### 方案 A：合集关系维护在 `collections.json`

- 新增文章时只改 `collections.json`；
- `articles.json` 不写 `collections` 字段；
- 构建脚本生成 `article.collections` 时反向汇总。

#### 方案 B：合集关系维护在 `articles.json`

- 新增文章时只改 `articles.json` 的 `collections` 字段；
- `collections.json` 的 `articles` 由脚本自动生成；
- 人工不再维护合集内文章列表。

建议选择 **方案 B**：

```text
data/articles.json 是唯一需要人工维护的文章数据；
data/collections.json 只定义合集标题、封面、描述；
合集与文章的关联关系由脚本自动生成。
```

这样新增文章时，最简流程可以缩短为：

1. 创建 HTML；
2. 在 `articles.json` 中加一条记录；
3. 运行 `python _tools/build_data.py --write`。

合集、搜索、下载、列表全部自动更新。
