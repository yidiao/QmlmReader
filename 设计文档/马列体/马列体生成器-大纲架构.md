1. 项目定位与核心思想

1.1 项目使命

本项目面向当代中国青年群体，旨在构建一个兼具传播力与教育力的 Web 端文本处理工具。表层功能是将日常文本转换为革命导师的行文风格，深层使命是通过这一转换过程，点亮文本中的批判性锋芒，强化其与现实议题的关联，并引导使用者溯源至马列主义经典文本，最终形成"兴趣触发 — 风格感知 — 经典阅读 — 自主表达"的学习自循环。

1.2 设计哲学：严肃活泼

马克思主义不是苦修。本项目拒绝两种倾向：要么严肃到让人望而却步，要么娱乐到消解理论的战斗力。

"严肃"是内核——论证逻辑的严密性、经典溯源的准确性、不回避阶级分析和矛盾揭露。
"活泼"是入口——反差感的惊喜、即时的风格转换反馈、分享卡片的社交传播力。

二者不是妥协关系。真正的严肃需要活泼来打开局面，真正的活泼需要严肃来赋予重量。概括为一句话：**让用户笑着进来，想着出去。**

1.3 核心定位

维度           | 定位描述
---------------|-------------------------------------------------
对用户         | 一个帮助你将日常表达升级为有立场、有逻辑、有战斗力的论述性文本的写作辅助工具
对经典         | 一座架设在现代生活语言与马列主义经典文本之间的修辞桥梁
对社会         | 一种以语言风格为媒介、以批判性思维为内核的青年文化现象

1.4 核心理念

"加密"不是掩饰，而是揭示。工具所做的"风格转换"，本质是将使用者原文中潜在的立场、判断与逻辑从模糊的日常语言中提炼出来，用导师们成熟的论述框架加以结构化呈现。它不是把"鸡汤"伪装成"革命语录"，而是帮助使用者看清：同一件事，用不同的语言骨架说出来，其批判深度与现实介入力截然不同。

1.5 底线原则

- 禁止庸俗化：任何转换结果不得将马列主义术语嫁接到职场晋升、情感鸡汤、消费主义等与历史唯物主义无关的议题上。
- 禁止错误类比：转换过程中不得将具体历史事件、人物进行不当类比或嫁接。
- 禁止立场伪造：工具不代用户立论，不伪造原文中不存在的政治立场与价值判断，仅在语言风格与逻辑结构层面操作。
- 禁止 AI 偏见放大：深度润色模式下，须在系统指令中显式约束大模型不得添油加醋或引入政治影射，输出结果须可溯源至已入库的规则或原文依据。


2. 目标用户与教育闭环设计

2.1 目标用户分层

用户画像   | 行为特征                                       | 预期路径                                     | 核心价值诉求
-----------|------------------------------------------------|----------------------------------------------|--------------------------------
游玩者     | 通过短视频/社交分享进入，输入趣味短句测试效果   | 即兴工坊 → 转换结果 → 截图分享 → 流失或进阶 | 趣味性、快速反馈、社交货币
表达者     | 有表达欲但缺乏论证方法，对现实议题有立场但不知如何有力陈述 | 即兴工坊 → 深度修习 → 复购使用             | 让自己的观点更有说服力、更有战斗力
学习者     | 对马列主义有一定基础，希望通过工具辅助阅读与写作 | 深度修习（高频）→ 经典溯源 → 自主写作       | 掌握导师的论证框架，内化为自身写作能力

2.2 "三阶跃迁"学习路径

阶段               | 用户状态                             | 工具动作                                                         | 学习目标
-------------------|--------------------------------------|------------------------------------------------------------------|----------------------------------------
第一阶：兴趣触发   | 被趣味内容吸引，输入短句测试         | 快速转换输出，附带风格标签                                       | 感知导师文风的差异化，产生"原来还能这样说"的认知冲击
第二阶：风格内化   | 开始用工具处理自己真正关心的议题     | 深度修习输出修改说明，标注"本次转换使用了《XX》中的XX句式"      | 理解特定修辞效果背后的逻辑骨架，能主动调用
第三阶：经典串联   | 形成稳定使用习惯，写作能力提升       | 关联推荐经典篇目："您本次转换的'诚然……然而……'结构，在马克思《路易·波拿巴的雾月十八日》第X段有典型运用。" | 从工具延伸到经典阅读，形成"工具→经典→工具"的知识内化循环

2.3 飞轮机制

游玩者通过短视频引流进入 → 体验趣味的转换效果 → 截图分享至社交平台 → 新游玩者涌入（飞轮启动）→ 部分用户产生进阶需求 → 使用深度修习 + 风格诊断 → 看到"您在第 3 段使用了类似恩格斯《自然辩证法》中的论证结构" → 溯源经典阅读 → 阅读后获得新认知，写出更有深度的文章 → 再次使用工具，获得更精准的转换效果 → 将高质量输出分享至社交平台 → 吸引更高阶的"表达者"与"学习者"进入。

飞轮的核心动力：每次工具使用都能产生可分享的成果，每次分享都在为"马列主义语言风格"这一文化现象做免费再传播。分享的驱动力不是"我在玩梗"，而是"我的表达变厉害了"。


3. 功能架构深化设计

3.1 "即兴工坊"的趣味性设计原则

"即兴工坊"承担引流入口功能，其趣味性不来自对马列主义的解构或戏仿，而来自反差感——让用户惊讶地发现：一句平平无奇的话，换成马克思/列宁的骨架说出来，竟然显得这么有力量。

趣味三要素：

- 即时对比：转换结果与原文并列显示，高亮被修改的词汇与句式结构，让用户直观看到"哪里变了"。
- 风格标签：输出结果附带简短说明（如"您这段话更像恩格斯在《反杜林论》中的综述风格"），而非强行搞笑。
- 一键分享卡片：自动生成包含原文、转换文、风格标签和工具名称的卡片，适配微信朋友圈、微博、B站动态等场景的图片规格。

红线：禁止"马克思看了都沉默"类戏谑表达；禁止"我宣布这是当代资本论"类不当类比；禁止将转换结果用于娱乐化解构严肃议题。

3.2 "深度修习"的经典溯源设计

深度修习输出的每一处关键修改，均关联到具体的原著依据：

修改点示例：
原文："经济在发展，但工人生活没有改善"
转换："生产的增殖与劳动者的贫困化，竟以相同的步伐推进。"
经典溯源：此句式仿自马克思《1844 年经济学哲学手稿》中"劳动者生产的财富越多，他就越贫困"的论证结构。建议延伸阅读：《1844 年经济学哲学手稿》"异化劳动"章节。

技术实现：在风格基因库中，为每一个句式模板、术语替换规则标注其出处（著作名称、章节、段落），当规则被触发时同步输出对应溯源信息。

3.3 现代化场景映射（"古为今用"的桥梁）

工具预设若干现代生活场景的示范性转换案例，展示在帮助页面或引导流程中：

日常表达                                         | 转换后（马克思路径）                                                                           | 教学要点
-------------------------------------------------|------------------------------------------------------------------------------------------------|----------------------------------
"最近工作压力大，工资也不涨。"                   | "劳动强度的持续攀升，与劳动力报酬的相对停滞，构成当代生产关系中一组日益尖锐的内在矛盾。"       | 将个人体验上升为结构性描述
"网上的人都在吵架，没有人认真讨论问题。"         | "公共言说空间的碎片化与情绪化，恰是理性对话机制被悬置的表征——但悬置不等于消解。"             | 让步-反驳结构提升论述深度
"我觉得这个政策不太对，但说不上来哪里不对。"     | "任何政策的效果评估，都须置于其与特定生产关系的互动中方能获得完整理解。"                     | 从主观感受转向客观分析
"为什么有人什么都不干却越来越富？"               | "财富的积累在当代条件下与劳动的付出相分离——这不是道德的沦丧，而是资本运动的内在逻辑。"       | 从道德追问转向结构追问
"房价这么高，我们这代人怎么办？"                 | "住房作为生存资料的属性与资本增殖逻辑之间的张力，正以一代人的生存焦虑为代价展开。"           | 将代际焦虑重述为生产关系的代际后果

重要说明：上述案例仅在"使用指南"页面展示，用于降低用户对"深度修习"功能的认知门槛。工具不预设任何"正确"的转换模板，所有转换均基于规则引擎对用户原文的实时分析。


4. 技术架构设计

4.1 整体架构：GitHub Pages + Vercel Serverless Functions

┌────────────── 用户浏览器 ──────────────┐
│                                         │
│  GitHub Pages（静态资源）                │
│  ├─ HTML/CSS/JS                         │
│  ├─ 规则引擎（纯前端执行）              │
│  └─ Canvas 分享卡片生成                  │
│         │                               │
│         │ 仅"深度润色"时触发             │
│         ▼                               │
│  Vercel Serverless Functions            │
│  └─ /api/translate（DeepSeek API 代理）  │
│                                         │
└─────────────────────────────────────────┘

设计原则：

- 规则引擎处理 90%+ 的请求，毫秒级响应，零 API 费用。
- AI 深度润色仅当用户主动点击"深度修习"按钮时触发，每次调用约 ¥0.01（DeepSeek API）。
- API Key 存储在 Vercel 环境变量中，绝不暴露到浏览器。
- 两个托管平台均提供充足的免费额度（GitHub Pages 无限流量，Vercel 每月 10 万次函数调用），学生完全可以负担。

4.2 规则引擎：前端实时转换核心

4.2.1 规则维度

维度     | 操作类型     | 示例
---------|-------------|-------------------------------------------------
词汇层   | 替换         | "发展" → "增殖与扩张" / "问题" → "矛盾"
句法层   | 重组         | 简单陈述句 → "诚然……然而……"让步结构
修辞层   | 插入         | 在论证关键处插入反问句或对偶排比
逻辑层   | 框架覆盖     | 现象描述 → 矛盾揭露 → 历史溯源 → 辩证反转

4.2.2 规则 JSON Schema

{
  "id": "marx-vocab-001",
  "author": "marx",
  "dimension": "vocabulary",
  "priority": 10,
  "pattern": "发展",
  "replacement": "增殖与扩张",
  "constraints": {
    "minContextLength": 5,
    "excludeIf": ["经济发展", "个人发展"]
  },
  "source": {
    "work": "资本论",
    "chapter": "第一卷 第二十四章",
    "quote": "剩余价值转化为资本，即资本积累……"
  },
  "status": "approved",
  "reviewed_by": "human"
}

4.2.3 匹配与执行策略

- 管线顺序：词汇替换 → 句法重组 → 修辞插入 → 逻辑框架覆盖（后阶段基于前阶段的输出）
- 冲突解决：当多条规则匹配同一文本片段时，取 priority 值最高者
- 性能：规则集 < 500 条时，O(n) 扫描即可，每秒可处理数百条请求

4.3 规则引擎与 AI 的分工边界

场景                   | 处理器       | 说明
-----------------------|-------------|-------------------------------------------------
日常短文本（≤200字）   | 规则引擎     | 规则覆盖率高，响应即时
术语/句式级替换         | 规则引擎     | 固定模式，无需 AI
段落级逻辑重构         | AI 深度润色  | 需要理解段落语义，规则难以穷举
用户原文中无明确立场   | 规则引擎为主 | 不代用户立论，仅做语言层包装
用户明确要求论证深化   | AI 深度润色  | 在用户同意的前提下，由 AI 补充论证框架

AI 触发条件：（1）用户主动切换到"深度修习"模式，（2）用户点击"AI 深度润色"按钮。两个条件缺一不可。当 API 不可用（超时、额度耗尽、网络故障）时，自动回退到纯规则引擎输出并给出提示。

4.4 文体知识注入层 — AI 生成能力的核心

4.4.1 问题诊断

V1.0 的 `api/translate.js` 中，每位导师的 System Prompt 仅有一句话：

```
斯大林：定义先行——"什么是列宁主义？列宁主义就是……"
将思想体系法典化。自问自答，逻辑逐步收网。
```

这一句话扔给 DeepSeek，它能做的就是在输出里塞几个"由此可见""问题在于"，但底层模型根本不理解斯大林的论证骨架长什么样。规则引擎同理——它匹配 `因此(.*)` 然后替换成模板，但不理解用户输入里的"因此"是在做因果推理还是在随口感慨。

核心缺口：**规则引擎和 AI 之间缺少一层"文体知识注入"**。这层不是凭空设计的——必须来自对导师原文的实际文本分析。

4.4.2 三层处理管线

```
用户输入
    │
    ▼
第一层：规则引擎预处理器（纯前端）
 ├─ 确定性词汇/句式替换
 ├─ 特征标签检测（含自问自答/含枚举/含因果推理/含反问）
 └─ 输出预处理文本 + 特征标签
    │
    ▼
第二层：文体知识注入（Vercel Function）
 ├─ 结构化 System Prompt（角色 + 句式规则 + 论证框架）
 ├─ Few-shot 示例嵌入
 ├─ 导师专属禁止事项
 └─ 接收特征标签作为上下文提示
    │
    ▼
第三层：DeepSeek API
 ├─ 接收增强 Prompt
 ├─ 生成符合目标导师文体的文本
 └─ 输出后处理
```

4.4.3 文体知识注入层的设计原则

1. **证据驱动，不是印象驱动**。每条句式规则必须能追溯到原文中的具体用例。不能凭"斯大林给我的感觉是……"来写 Prompt。

2. **分层结构，不是扁平描述**。Prompt 分为四层：
   - 角色定义（"你是谁"——基于三维分析框架的定论者定位）
   - 句式规则（"怎么写"——每条附带原文证据引用）
   - 论证框架（"如何处理任意输入"——通用操作流程）
   - 禁止事项（"绝对不能做什么"——与其他导师的句式边界）

3. **导师专属，不是通用模板**。每位导师的 Prompt 是独立的、基于各自原文分析的。斯大林 Prompt 中的"禁止使用反问句"在列宁 Prompt 中恰恰是要求。

4. **可验证，不是黑盒**。每条句式规则附带原文证据引用。当转换效果不好时，可以回溯到"是 Prompt 规则写错了"还是"原文证据本身就选错了"。

4.5 规则引擎与文体知识注入层的协作

规则引擎的预处理输出有两个用途：

1. **预处理文本**：经过词汇/句式替换后的文本，作为 AI 的输入。规则引擎处理后的文本已经具备部分文体特征（术语已替换、简单句式已重组），降低了 AI 的理解难度。

2. **特征标签**：规则引擎检测到用户输入中的句式特征后，生成标签传给文体知识注入层：
   - `含自问自答结构` → Prompt 中强调"使用自问自答链驱动论证"
   - `含多因素分析` → Prompt 中强调"使用第一…第二…第三枚举结构"
   - `含因果推理` → Prompt 中强调"使用因此/由此可见收网"
   - `含反问/质疑` → Prompt 中强调"使用有人会问…预判异议模式"
   - `含感性陈述` → Prompt 中强调"将个人体验提升为结构性描述"

这种协作方式让规则引擎从"独立输出文本"的角色转变为"为 AI 提供上下文提示"的角色——两者不再各自为政，而是形成一条完整的处理管线。


5. AI 蒸馏规则库流程设计

本章描述如何利用大语言模型一次性从马列主义经典著作中批量提取风格规则。这是规则引擎的知识源头——一次投入，持续使用。

5.1 方法概述

- 这是一次性的离线处理流程，不是每次用户请求时运行。
- 核心思路：将经典文本切分为段落，喂给大模型，使用结构化输出（JSON Schema）批量提取多维度风格规则。
- 提取结果经人工审核后入库，成为规则引擎的生产规则。
- 预计花费：处理全部四导师代表作约 40-60 个核心段落，DeepSeek API 花费约 ¥5-10。

5.2 原始语料准备

来源                                       | 选取原则
-------------------------------------------|-----------------------------------------------
《共产党宣言》《资本论》第一卷              | 马克思：理论体系建构 + 辩证论述
《反杜林论》《自然辩证法》《费尔巴哈论》    | 恩格斯：通俗化阐述 + 自然辩证法
《怎么办》《国家与革命》《帝国主义论》      | 列宁：论战文体 + 组织化论述
《毛选》1-4 卷（重点：矛盾论、实践论）      | 毛泽东：中国化表达 + 军事比喻体系

选取标准：
- 每个导师选取 10-15 个代表性段落，每段 500-2000 字。
- 均衡覆盖理论阐述、论战驳斥、历史叙事、政治宣言、策略分析等文体。
- 优先选取句式特征鲜明、术语密度高的段落。

5.3 提取维度与 Prompt 设计

向大模型发送的提取指令应包含以下五个维度的 Prompt，以结构化的 JSON Schema 约束输出：

维度     | 说明                                         | 提取要求
---------|----------------------------------------------|-------------------------------------------------
词汇层   | 高频术语、特征修饰语、辩证副词用法           | 输出"原词 → 替换词"映射对 + 使用场景说明
句法层   | 句式长度分布、排比结构、反问句、"诚然…然而…"类让步结构 | 输出句式模板 + 占位符标记 [A][B]
修辞层   | 隐喻域（军事/有机/建筑）、反讽模式、夸张与克制 | 输出修辞类型 + 原文例句 + 修辞功能分析
逻辑层   | 正反合三段式、唯物论反转（"不是 X 决定 Y…"）、阶级主体框架 | 输出论证骨架 + 对应的原文段落
情感层   | 义愤语域、革命乐观主义、学理节制             | 输出情感标签 + 触发该情感的上下文条件

关键 Prompt 原则：
- 要求逐字照录原文（source_text 必须与原段落精确匹配），不允许 AI 改写或概括。
- 要求规则按维度分类输出，每个维度 3-8 条，宁缺毋滥。
- 对每位导师分别执行提取，跨导师比较留到人工审核阶段。

5.4 输出格式与规则入库流程

LLM 提取 → JSON 格式规则候选项 → 人工审核（验证原文匹配、排除臆造、标注质量分）→ 入库（status: "approved"）→ 编译为前端规则引擎格式 → 部署

人工审核检查清单：
- [ ] source_text 是否在原文中能找到精确匹配？
- [ ] 提取的句式模板是否具有代表性（而非偶然出现一次）？
- [ ] 术语替换是否保持了语义一致性（不发生意义漂移）？
- [ ] 是否存在庸俗化或不当类比？

5.5 规则维护与迭代

- 版本控制：规则库采用语义版本号（如 v1.2.0），每次更新记录 changelog。
- A/B 测试：新增规则通过 feature flag 灰度发布，对比用户满意度后决定全量上线。
- 社区贡献管线：用户在使用中通过反馈入口提交"规则建议" → 人工审核 → 合并入库。


6. API 安全与架构设计

本章描述 AI 深度润色功能的 API 代理层设计。核心参考：zhouli-translator 项目（MIT 开源）的安全实践。

6.1 架构原则

- API Key 绝不进入浏览器。Key 作为 Vercel Environment Variable 存储，仅在 Serverless Function 运行时读取。
- Vercel Function 作为轻量代理：接收 `{text, author, mode}` → 校验 → 拼装 System Prompt → 转发 DeepSeek → 返回结果。
- 浏览器只看到一次 `POST /api/translate` 请求，返回纯 JSON `{result, diagnostics, sources}`。

6.2 速率限制

限制类型         | 阈值              | 实现方式
-----------------|-------------------|---------------------------------
每 IP 窗口限制   | 10 次 / 10 分钟   | 内存 Map，滑动窗口
每 IP 每日限制   | 30 次 / 天         | 内存 Map + 日期标记
并发限制         | 单 IP 同时仅 1 个请求 | 请求级锁（Promise tracker）

注意：内存 Map 在 Vercel Function 冷启动时会重置。这是免费层级的可接受折衷——生产级部署时可替换为 Upstash Redis（也提供免费额度）。

6.3 Prompt 注入防御

参考 zhouli-translator 的 `lib/prompt-security.ts`，在 API 端实现四类攻击检测：

- 指令暴露探测：检测"system/系统/prompt/指令/hidden/隐藏"等关键词。
- 身份覆写探测：检测"ignore previous/忽略之前的/you are now/你现在是/ pretend/假装"等角色劫持模式。
- 输出格式操纵：检测"reply in JSON/输出 JSON/用表格回复"等格式注入。
- 原文提取企图：检测"tell me your/告诉我你的/show me the prompt/展示你的提示词"等提取请求。

检测到注入时，不阻塞请求，而是返回精心编写的"恶意输入文体化改写"结果——即将用户试图攻击的行为本身用马列体表述出来，同时不执行任何实际攻击指令。

6.4 内容安全

输入侧：
- 最大长度限制：2000 字（深度润色）/ 500 字（即兴工坊）。
- 敏感词库匹配 + 正则拦截，遇敏感输入返回中性提示："您提交的内容涉及本工具暂不处理的话题，请调整后重试。"

输出侧：
- 系统指令中添加负面约束："禁止将原文内容与任何历史事件、政治人物进行类比、影射或联系；禁止添加原文中不存在的政治立场；禁止使用具有人身攻击性质的表述。"
- 输出后处理：检测生成结果中是否包含越界内容，若检测到则回退为"规则引擎结果 + 安全提示"。

6.5 CORS 与部署安全

- 允许来源白名单：`qmlmreader.github.io`、`localhost`。
- 环境变量绑定：`DEEPSEEK_API_KEY` 通过 Vercel Dashboard 设置，不写入仓库。
- 发布前审计脚本：扫描 git 追踪文件中的 API Key、Bearer Token、私钥块，防止误提交。
- `.env` 文件已加入 `.gitignore`。

6.6 日志与隐私

- 最小日志：仅记录时间戳、输入字符数、目标作者、响应耗时、成功/失败状态。
- 不存储用户输入文本或 AI 输出文本。
- 无 Cookie、无用户画像、无第三方追踪。
- 隐私说明页面明确数据边界和保留策略。


7. 前端视觉设计方向

7.1 核心设计语言：苏维埃构成主义 × 中国革命美术

本工具不模仿 zhouli-translator 的东方古典美学——那是"周礼"的皮肤。马列体的视觉语言应根植于自身的传统：20 世纪初的构成主义设计（罗德琴科、利西茨基）与中国革命宣传画的融合。

构成主义基因：大胆几何造型、斜线分割、有限色板、无衬线字体主导、功能先于装饰。
中国革命美术基因：红色为绝对主色、金色/黄色为辅助、星星/镰刀/锤子图形元素、标语式排版。

二者交汇处产生一种独特的美学：理性、有力量、不煽情，但也不冷漠。

7.2 配色方案

色值         | 角色           | 来源
-------------|----------------|--------
`#c41e3a`    | 主红           | 继承 Qmlmreader
`#8b0000`    | 深红（渐变底） | 继承
`#ffd700`    | 金（强调）     | 继承
`#1a1a1a`    | 印刷黑         | 新增——构成主义色块底色
`#f5f0e8`    | 纸张米白       | 新增——替代纯白背景，更温暖
`#c4c4c4`    | 苏联灰         | 新增——次级 UI 元素
`#2a2a2a`    | 暗色模式底色   | 新增

7.3 字体策略

- 正文：系统无衬线字体栈（`-apple-system, "Microsoft YaHei", sans-serif`），不加载外部字体，保持加载速度。
- 标题/强化文字：横幅区域可选用 `"Noto Serif SC", "STSong", serif` 做衬线标题，制造"标语"感。
- 输入/输出区域：系统等宽或 UI 字体，保证可读性。

7.4 视觉元素

- 几何分割线：粗红线块（4px 高）、斜线分割符（CSS border 旋转 45°）。
- 卡片：构成主义"浮动矩形"——白色/米白底 + 偏移黑色阴影（`box-shadow: 6px 6px 0 #1a1a1a`），视觉重量感强。
- 半调网点纹理：CSS `radial-gradient` 模拟印刷网点，覆盖在主要卡片上增强材质感。
- 角落支架装饰：卡片四角用 CSS border 实现 L 形双线装饰（参考 zhouli 的 corner ornament 思路，但用几何直线替代回纹）。
- 图标：纯 CSS/SVG 几何图形（五角星 ☆、箭头 →、齿轮 ⚙），不依赖图标库。
- 分享卡片：粗体字排版构图，适合朋友圈/微博信息流。

7.5 动效原则

- 克制：不使用弹跳、旋转等"花哨"动效。转换完成的文字以"逐字打印"或"印章落下"效果呈现——暗示文本是被"锻造"出来的。
- 所有过渡时间 150-200ms，减少运动敏感用户的负担（支持 `prefers-reduced-motion`）。
- 按钮 hover：轻微偏移（`translateY(-1px)`）+ 阴影加深。

7.6 响应式策略

- 桌面（≥768px）：输入与输出并排显示，左侧原文，右侧转换文，中间红色竖线分隔。
- 移动（<768px）：输入在上，输出在下，堆叠布局。
- 分享卡片预览统一缩放到容器宽度，实际下载为 1080×1440 全分辨率。
