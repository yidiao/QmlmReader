# 数据源维护规范

> 作用：记录 QmlmReader 数据层的权威来源、索引层与正文层分工、构建接口和维护边界。  
> 使用方式：凡涉及文章索引、正文 JSON、合集、搜索、下载中心、站点数据构建的任务，必须先读本文。

---

## 一、数据层总原则

QmlmReader 当前已经明确采用 **双层数据结构**：

### 1. 索引层

负责：

- 文章列表
- 作者/分类/年代筛选
- 搜索索引基础字段
- 文章页路由入口
- 下载中心条目入口
- 合集映射

权威文件：

```text
data/articles.json
```

### 2. 正文层

负责：

- 文章标题与正文元信息
- 段落化正文
- 章节分组
- 页面原文 tab 的内容来源
- TXT / DOCX 导出的正文来源

权威目录：

```text
data/articles-json/{Mentor}/{Star}/{slug}.json
```

### 3. 辅助元数据层

负责：

- 文章页与正文源的映射
- 校验快照
- 辅助生成信息

统一目录：

```text
data/articles-json/_meta/
```

---

## 二、目录结构规范

`data/articles-json/` 现在只允许保留以下顶层：

```text
data/articles-json/
  Engels/
  Lenin/
  Mao/
  Marx/
  Stalin/
  _meta/
```

### 1. 正式正文数据路径

```text
data/articles-json/{Mentor}/{Star}/{slug}.json
```

示例：

```text
data/articles-json/Mao/★★★★★/shi-jian-lun.json
data/articles-json/Lenin/★★☆☆☆/lun-wo-guo-ge-ming.json
```

### 2. 禁止结构

以下结构视为旧遗留，禁止继续生成：

```text
data/articles-json/★★★★★/{slug}.json
data/articles-json/★★★★☆/{slug}.json
data/articles-json/★★★☆☆/{slug}.json
```

### 3. `_meta` 用途

目前 `_meta/` 内允许存在：

```text
data/articles-json/_meta/manifest.json
data/articles-json/_meta/manifest.generated.json
data/articles-json/_meta/validation.json
data/articles-json/_meta/validation-final.json
```

这些文件是工具辅助文件，不是文章正文。

---

## 三、索引层：`data/articles.json`

### 1. 作用

`data/articles.json` 是全站文章索引，不是正文仓库。

它负责：

- 文章卡片列表
- 文章分类/筛选
- 文章路径 `file`
- 搜索基础索引
- 下载中心文章入口
- imported 条目是否已入站

### 2. 核心字段

```json
{
  "slug": "shi-jian-lun",
  "title": "实践论",
  "author": "毛泽东",
  "authorKey": "mao",
  "date": "1937年7月",
  "year": "1937",
  "priority": 5,
  "category": "哲学基础",
  "type": "philosophy",
  "keywords": ["认识论", "辩证法", "实践"],
  "file": "articles/Mao/shi-jian-lun.html",
  "ready": true,
  "collections": ["mao-vol1", "mao-philosophy"]
}
```

### 3. 当前状态说明

- 当前总条目数已扩展到 imported + 正式文章的总量
- 其中手工精读页条目并不等于 `articles-json` 正文条目
- 目前仍缺少《论我国革命》的索引条目，需要后续补齐

## 四、正文层：`data/articles-json`

### 1. 当前目标模型

每篇文章推荐结构：

```json
{
  "title": "实践论",
  "mentor": "Mao",
  "star": "★★★★★",
  "slug": "shi-jian-lun",
  "source": "原始资料路径",
  "meta": {
    "author": "毛泽东",
    "subtitle": "关于认识和实践的关系——知和行的关系",
    "date": "1937年7月",
    "category": "哲学基础 · 辩证法",
    "wordCount": "约9,400字",
    "lengthTag": "中篇"
  },
  "original": {
    "titleLine": "实践论 ——论认识和实践的关系——知和行的关系",
    "paragraphs": ["..."],
    "chapters": [
      {
        "title": "一 认识和实践",
        "paragraphs": ["..."]
      }
    ]
  }
}
```

### 2. 兼容现状

目前仓库内还并存几类旧字段：

- `content: "长字符串"`
- `content: { value: "..." }`
- `paragraphs: "长字符串"`

这些属于过渡结构，长期应统一迁到：

- `meta`
- `original.paragraphs`
- `original.chapters`

### 3. 段落维护原则

- 优先基于原始 TXT 重新提取段落
- 不要把整篇压成单行或单字段巨串
- `paragraphs` 必须是真实可维护段落数组
- `chapters` 是阅读组织层，不是必须与原始目录完全一致，但要可解释、可维护

## 五、辅助元数据：`_meta`

### 1. `manifest.json`

用途：记录文章 HTML 与正文源的人工/工具映射。

### 2. `manifest.generated.json`

用途：基于正文目录补出 JSON 路径后的派生清单。

### 3. `validation.json`

用途：记录页面级接口校验，例如：

- 是否含 tab
- 是否含 original 区块
- 是否接入 `article-common.js`
- 是否接入 JSON 正文

### 4. `validation-final.json`

用途：记录面向巡检的摘要统计，例如：

- 文件名
- 是否存在 tab
- 字符数
- 标题

## 六、构建产物与接口

### 1. 站点聚合数据

生成文件：

```text
js/site-data.js
```

生成命令：

```bash
python _tools/build_data.py --write
```

### 2. `site-data.js` 当前职责

```js
window.SITE_DATA = {
  generatedAt: "by build_data.py",
  collections: [],
  articles: [],
  articleIndex: [],
  galleryIndex: [],
  rectifyIndex: [],
  downloadData: {}
};
```

说明：

- `site-data.js` 目前仍然聚合索引层数据
- 它不是正文全文仓库
- 正文层逐步改为按页单独读取 `articles-json`

## 七、页面读取关系

### 1. 文章列表页

- `html/articles/articles.html`
- 读取 `data/articles.json` 或 `window.SITE_DATA.articles`
- 不直接承担正文展示

### 2. 精读页

- `html/articles/{Mentor}/{slug}.html`
- 原文 tab 应逐步从 `data/articles-json/...` 读取
- 精读模块仍可保留在 HTML

### 3. 下载导出

- `js/download-export.js`
- 优先读取文章页声明的 `data-article-json`
- 从正文 JSON 导出 TXT / DOCX
- 未 JSON 化页面才退回 HTML 抽取

---

## 八、构建与维护规则

### 必须遵守

1. 不要手工编辑 `js/site-data.js`
2. 不要再把顶层星级目录当正文正式目录使用
3. 不要把 `_meta` 文件和正文 JSON 混放到同一级职责里
4. 正文结构化改造优先在 `articles-json` 完成，再让页面读取
5. 涉及文章列表、筛选、统计、下载入口时，优先更新 `data/articles.json`

### 推荐顺序

1. 改 `data/articles.json` 或 `data/articles-json/...`
2. 改对应页面或脚本
3. 运行：

```bash
python _tools/build_data.py --write
```

4. 再验证页面
