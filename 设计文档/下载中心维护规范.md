# 下载中心维护规范

> 作用：记录下载中心的数据接口、资源来源和导出规则。  
> 使用方式：涉及下载页面、TXT / DOCX 导出、manifest、文章下载入口的任务先读本文。

---

## 一、当前定位

下载中心的方向已经明确为：

> **下载入口统一展示，正文内容按需导出，不再长期维护多份静态正文成品。**

对于文章类资源，当前主目标是：

- 用户在下载中心或文章页点击下载
- 弹出格式选择
- 统一支持：`TXT` / `DOCX`
- 导出内容优先来自文章正文 JSON

---

## 二、页面与数据位置

页面：

```text
html/downloads/downloads.html
```

权威清单：

```text
downloads/manifest.unified.json
```

兼容清单：

```text
downloads/manifest.json
```

站点聚合产物：

```text
js/site-data.js
```

相关脚本：

```text
js/download-export.js
```

数据构建脚本：

```bash
python _tools/build_data.py --write
```

---

## 三、前端读取接口

`html/downloads/downloads.html` 当前从：

```js
window.SITE_DATA.downloadData
```

读取三类数据：

- `articles`
- `rectify`
- `posters`

文章下载项当前的关键字段示例：

```json
{
  "title": "实践论",
  "author": "毛泽东",
  "cat": "mao",
  "slug": "shi-jian-lun",
  "year": 1937,
  "file": "articles/Mao/shi-jian-lun.html"
}
```

说明：

- `file` 现在指向文章页 HTML
- 下载时由 `download-export.js` 再去解析正文源

---

## 四、正文来源规则

### 1. 第一优先级：`data-article-json`

如果文章页 `<body>` 声明了：

```html
<body data-article-json="../../../data/articles-json/Mao/★★★★★/shi-jian-lun.json">
```

那么下载脚本应：

1. 先读取文章页 HTML
2. 识别 `data-article-json`
3. 再读取对应 JSON
4. 用其中的正文导出 TXT / DOCX

### 2. 第二优先级：HTML 抽取

如果页面尚未 JSON 化，则：

- 从 HTML 内现有正文结构中抽取段落
- 作为过渡方案导出

---

## 五、资源策略

### 文章类

- 主格式：即时导出的 `TXT` / `DOCX`
- 不再主推预生成 PDF / TXT 正文副本

### rectify 类

- 可继续按当前站内资源结构维护
- 后续再决定是否也改为统一导出模型

### 宣传画 / 大包资源

- 不强制本地打包 ZIP 托管
- 可改为外链承载
- 下载中心只展示入口和说明

---

## 六、manifest 维护规则

### 1. `downloads/manifest.unified.json`

它负责下载入口索引，不是正文仓库。

### 2. 推荐字段

建议逐步统一为：

```json
{
  "title": "实践论",
  "author": "毛泽东",
  "cat": "mao",
  "slug": "shi-jian-lun",
  "year": 1937,
  "file": "articles/Mao/shi-jian-lun.html",
  "status": "ready",
  "formats": ["txt", "docx"],
  "sourceType": "article-page"
}
```

### 3. 不要做的事

- 不要把全文正文写进 download manifest
- 不要再为每篇文章维护一份静态 PDF / TXT / DOCX 成品路径作为主方案
- 不要让 manifest 脱离文章页与正文源实际状态

---

## 七、文章页与下载中心的边界

现在的约定是：

- 下载逻辑由 `js/download-export.js` 统一承担
- 下载入口主要放在 `html/downloads/downloads.html`
- 精读页可以不再提供下载按钮

这意味着：

- 下载中心继续作为唯一主要下载入口
- 文章页只负责阅读与精读组织
- 正文一旦切到 `articles-json`，下载中心也会直接受益

---

## 八、当前维护重点

1. 继续让经典文章页逐步接入 `data-article-json`
2. 确保下载优先走 JSON 正文，而不是 HTML 正文副本
3. 让下载中心保持主入口地位，不再把下载浮窗分散到各篇精读页
4. 后续再细化资源状态、外链、大包托管等模型
