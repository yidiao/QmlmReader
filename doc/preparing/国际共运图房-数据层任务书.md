## 0. 一句话目标

在不触碰交互层代码的前提下，按既定数据契约扩充图房的两条数据管线——**地图截面**（atlas.json）与**史实日历**（history-events.js）——让时间之轴的第二层陈列更多年份、让 641 条史实继续生长，每一条都有出处。

## 1. 现状资产与数据契约（字段即合同，改字段名/删字段=破坏交互层）

### 1.1 `data/international/atlas.json`（约 136KB，地图与检索室真源）

- `sources`: `{ id: {title, url, kind, date} }` —— 全库出处登记处，events/organizations/features/camps 通过 `sources:[id]` 引用。**每条新增数据必须在此登记**
- `events[]`（44 条）: `{id, title, date(显示串), country(countries 键), era(时代 id), category(ideas|organization|revolution|debate|transition|present), summary, paragraphs[], question, sources[], keywords[](可选)}`
- `organizations[]`（12 条）: `{id, title, short, asOf, country, form(armed|public|transition|uncertain), lineage(maoist|mao-origin|communist|legacy-maoist), status, summary, history, position, limits, sources[]}`
- `countries`: `{ ISO2: [中文名, 洲, [lon,lat]] }`（lon/lat 仅供球面模式；标点位置取几何中心）
- `eras[]`（6 条）: `{id, title("起—止 · 语义名"), start, end, subtitle, paragraphs[]}`——**eraOfYear() 按年份归属，新增截面年份若超出现有时代区间需同步扩 era**
- `features`: `{comintern:{title,paragraphs[],sources[]}, genealogy:[[标题,段落],…]}`
- `camps`:
  - `snapshots[]`（24 条）: `{id("1949"|"1919-01"), date("1949-12-31"), title, notes, activeStates[], uncertainStates[], members{ISO:阵营}, nature{ISO:性质}, routeNote, sources[]}`——**截面切换换装的全部依据**
  - `states[]`: `{id, title, start, end, kind(socialist|orientation|partial), precision(year=只到年份), geography[ISO], url, note, sources[]}`
  - `federations`、`armedAreas`、`capitals{ISO:[全名,城市,lon,lat]}`、`colors/natureColors`
- 中国红是显示约定（world-50m.json `displayPolicy.chinaRedFromYear:1949`），数据侧只管把截面日期写准，红色自动生效

### 1.2 `data/history-events.js`（641 条，史实日历唯一真源）

- `const historyData = { 1:[…], 2:[…] … 12:[…] }` 按月分组
- 条目: `{year, date("1月7日"), title, desc, category(revolution|war|political|person|culture), nature(positive|negative|neutral), img(""=占位,可选), think(可选), links([{label,href}],可选)}`
- 注意：日历抽屉与密度曲线都实时读它；**字段名是契约**

### 1.3 交互层合同速查（不可破坏）

- `js/international/international-atlas.js` 公开钩子：`getData/getCamera/projectLL/flyToLL/onDraw/clearSelection/getState/getWrapWidth`——签名不动
- 时间之轴第二层已做密度自适应：截面 >16 隐国名、>30 缩年份字号；**按住第二行横扫 = 拖拽滑块**。补充年份不需要动交互层
- URL 只承载 `snapshot`；localStorage：`qmlm:canvas:seen`（封面）、`qmlm:canvas:stations:v2`（站牌）、`qmlm:canvas:axis-row2-pinned`（截面行钉住）、`qmlm:canvas-drawn`（随机回眸）
- 缓存纪律：改任何 css/js 必须 bump HTML 里的 `?v=` 参数（浏览器缓存陈旧脚本坑过多次）

## 3. 爬取与核验纪律（用户命令级）

- **WebSearch 核到原文页才写入**；权威二手需两个独立来源交叉；百科条目不算原文
- 每条事实落 `sources`：`{title, url, kind(历史原文|政府报告|新闻|研究|当事组织文件), date}`；**立场必须可辨**——当事组织的自我定位、政府报告、新闻、研究各自标注，不混用
- 日期精度不足只写年份（`precision:"year"` 惯例），不伪造具体日期；旧资料不冒充今日活动证据
- **不整段转载版权文本**：引事实 + 出处链接，转述不抄录
- 朋友工程（D:\AI Pj\international-communist-atlas-main）数据只可当**线索**，不可当出处；其"一眼错"前科在案
- 领土/政权表述敏感面：沿用现有口径（台湾在中国面内、藏南按官方底图、分治用斜纹不伪绘历史疆界、"历史共产党执政/人民民主/其他社会主义取向"分开列示）

## 5. 明确不做

- **不改交互层**（css/js/html）：发现交互 bug 记录到 `doc/learnings.md` 并在交付时报给用户，**不顺手修**——上一轮"边修边坏"的教训
- 不动 `js/site-data.js`（生成物，勿手改）
- 不删/不改四个子页（日历/专栏/时事/纪念）
- 不引入构建步骤、后端、npm 依赖；纯静态
- 不照抄朋友工程的默认设定与"一眼错"

## 6. 工作方式

1. 一次只改一份数据文件；JSON 改动用 `node -e "JSON.parse(...)"` 或 `node -e "require(...)"` 校验语法后再上浏览器
2. 本地验证：`python -m http.server 8642`（根=Qmlmreader），页面 `/html/international/international.html`；改 js/css 后 bump HTML 的 `?v=`
3. 数据核对用独立标签页，亮/暗双主题各看一遍
4. 每完成一个任务块，跑一遍 §4 回归清单
5. 改动全部留在本地，是否提交由用户决定
6. 爬取批次建议：一次 3-5 个截面或 20-40 条史实，核验完一批写入一批，不做无出处的一次性大填灌
