## 二、已落地的静态侧加固（2026-11-08 竣工）

**工具**：`_tools/add_security_meta.py`，三模式，幂等可复跑：

```
python -I _tools/add_security_meta.py --scan    # 外域扫描 + 强制CSP前提核查 + 允许清单比对
python -I _tools/add_security_meta.py --apply   # 注入（已含标记自动跳过，2026-11-08 已跑：1347/1347）
python -I _tools/add_security_meta.py --remove  # 摘除本工具注入块（回滚用）
```

**注入内容（v1，共 4 行，紧跟 `</title>` 之后）**：

1. `<meta name="referrer" content="strict-origin-when-cross-origin">` — 强制生效（与现浏览器默认一致，零风险）
2. 强制 CSP：`object-src 'none'; base-uri 'self'; form-action 'self'` — 扫描确认全站无 object/embed/base/form/iframe 标签，零破坏
3. Report-Only CSP 全量允许清单（见下），转正前观察用

**允许清单依据（2026-11-08 全站扫描）**：

| 外域 | 用途 | CSP 桶 |
|---|---|---|
| cdn.jsdelivr.net | `<script>` chart.js（34 页） | script-src |
| unpkg.com | `<script>` mammoth（小册子） | script-src |
| fonts.googleapis.com | Google Fonts 样式表 | style-src |
| fonts.gstatic.com | 字体文件 | font-src |
| api.deepseek.com | 前端 BYOK 直连 ×3 | connect-src |
| qmlm-reader.vercel.app | API 代理地址（`QMLM_API_BASE`） | connect-src |
| bilibili/pan.baidu/s.shuge.org/platform.deepseek 等 | 纯超链接（导航不受 CSP 约束） | 不进清单 |
| en.wikipedia.org 等 lineage-data.js 引用串 | 资料来源链接数据（x1700+） | 不进清单 |

**已知限制**（meta 形式固有的，留待反代层补）：

- `X-Content-Type-Options`、`frame-ancestors` 无法经 meta 下发
- Report-Only 无收集端点，违规只进浏览器控制台；个别旧浏览器可能忽略 Report-Only meta（仅损失观察手段，无功能影响）

**CSP 转正路径**：在关键页（马列体、小册子、青马、画廊、拼图）开控制台确认无 Report-Only 违规报告后，把 Report-Only 内容并入强制 CSP（工具里两常量合一，重跑 `--apply` 前先 `--remove`，或改 v2 标记）。

## 三、DDoS 分层防御蓝图（自建服务器时启用）

| 层 | 措施 | 说明 |
|---|---|---|
| L3/L4 洪水 | **Cloudflare 免费档套在前面**，源站 IP 绝不暴露 | 单台 VPS 物理上防不了流量攻击，唯一答案是上游过滤；CF 代理后攻击者只能打到 CF |
| L7 洪水 | 反代层限流：Nginx `limit_req`/`limit_conn`（或 Caddy） | CF 漏网之鱼在网关层掐掉 |
| 系统层 | 防火墙只开 80/443、SSH 仅密钥登录 + fail2ban | 自动化扫描天天打 SSH，自建第一天就会遇到 |
| 经济层 | AI 代理：移植 `api/translate.js` 现有防护（CORS 白名单/长度限制/注入正则/清洗）+ 网关限流 + DeepSeek 平台侧消费限额 | 低流量盗刷比大流量 DDoS 更可能发生 |
| 合规层 | 国内服务器需 ICP 备案；境外 VPS 无备案但延迟高 | 影响后续所有选型，先拍板 |

**源站 IP 隐蔽要诀**（接入 Cloudflare 第一天核查三处）：DNS 历史记录、外发邮件头、证书透明度日志都会泄露源站；泄露后 CF 免费档形同虚设。

## 四、自建服务器迁移清单（照单执行）

### 部署架构

1. Cloudflare 接入 → 隐藏源站 IP
2. 反代 Nginx/Caddy：TLS（Caddy 自动签）、`limit_req`/`limit_conn`、`client_max_body_size` 收紧、超时收紧、补安全响应头（`nosniff`、`X-Frame-Options`——meta 补不了的两个，与 meta CSP 双保险）
3. 系统层：ufw 只开 80/443、SSH 仅密钥、fail2ban、unattended-upgrades、非 root 服务用户
4. 静态托管直接复用本仓库产物（index.html + html/ + assets 等）；`data/` 不对外

### AI 代理接口（唯一经济攻击面）

1. `api/translate.js` 的防护逻辑可直接移植（CORS 白名单、长度上下限、注入正则、输出清洗）
2. 限流改跨实例存储（Upstash Redis 免费档 / nginx 网关前置限流），内存 Map 在多实例下失效
3. **DeepSeek 平台侧设消费限额——无论部署在哪，这条先做**
4. 503 文案去内部细节（`api/translate.js:357` 暴露"未配置 DEEPSEEK_API_KEY"）

### 仓库与运维

- 仓库公开 = doc/、_tools/ 全公开，2026-11-08 已核对内容可接受；无 .env/密钥文件入库
- 备份 3-2-1；可用性监控（uptime-kuma 等，可选）

## 五、决策点（⬜ 均待所有者裁定）

- ⬜ 国内服务器（ICP 备案）还是境外 VPS（无备案、延迟换）
- ⬜ Cloudflare 接入时机：部署当天即接（推荐）还是先裸奔观察
- ⬜ Report-Only CSP 转强制 CSP 的时机（需人工开控制台核对关键页）
- ⬜ AI 代理限流存储选型：Upstash Redis（免费档、免自管）vs nginx 网关限流
- ⬜ P2 小清理（vercel.json 删 x-client-id 死配置 / ALLOWED_ORIGINS 精简 localhost / 503 文案）何时做——恢复 Vercel 或自建时顺手
